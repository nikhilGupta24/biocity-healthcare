03 · Methodology / Playbook

The repeatable five-act method

This is the spine of the engagement. The same five acts work for almost any "modernise this product and sell it to stakeholders" brief.

  1. Audit & empathise. Open the current product as a real user. Write down the concrete problems (clutter, slow, hard to find, no trust). Frame everything later as a fix to one of these — never "change for change's sake."
  2. Prototype the destination, not a deck. Build a real, clickable artifact early. A working prototype convinces stakeholders far more than slides, and it forces you to make real design decisions.
  3. Design a system, then apply it. Define tokens (colour, type, spacing, radius, shadow) once as CSS variables. Everything downstream — website, CRM, demos — reads from the system, so it stays consistent and re-themeable (incl. dark mode) for free.
  4. Translate for the audience. Engineers think in features; CEOs think in outcomes, effort and time. Re-label everything: "schema markup" becomes "so Google & AI understand you." Tag each item by business goal and effort.
  5. Package the pitch. Wrap it in a narrative: problem → see the fix → the plan → the timeline → what we need → why it pays off. Make it interactive so they explore, and printable so they can forward it.
Principle

Show, don't tell. A drag-to-compare slider, a live device toggle, or a one-tap element demo lands an idea in seconds — where a paragraph would lose the reader.

04 · Design System & Techniques

The craft toolkit behind the look

These are the concrete, copy-paste-able techniques that make the work feel premium. Master these and you can reproduce the quality anywhere.

1 · Token-driven theming (and free dark mode)

Define the whole palette as CSS variables on :root and override them under a [data-theme="dark"] selector. Components only ever reference variables — never raw hex. A single attribute flip re-themes the entire page, and the choice is remembered in localStorage.

:root{ --bg:#F5F7F8; --ink:#0E1B1A; --accent:#0E9E8C; }
[data-theme="dark"]{ --bg:#0A1110; --ink:#EAF2F0; --accent:#2DD4BF; }
/* usage */ .card{ background:var(--bg); color:var(--ink); }

2 · The "siteskin" scoping trick

When you embed a preview of one brand inside a document with a different brand (e.g. the coral website demo living inside the indigo plan), wrap the preview in a class that re-declares the tokens locally. The preview keeps its own identity while the host keeps its own.

.siteskin{ --accent:#E05A3A; --panel:#FFF; font-family:'Plus Jakarta Sans'; }
<div class="demo-stage siteskin"> ...website preview... </div>

3 · Typography pairing

A characterful display face for headings + a clean workhorse for body. We used Fraunces (warm serif) for the website, Space Grotesk for the strategy/docs headings, and Inter / Plus Jakarta Sans for body. One display + one body is plenty.

Fraunces — website displaySpace Grotesk — docs headingsInter — bodyJetBrains Mono — code

4 · Micro-interactions & motion

  • Reveal on scroll: an IntersectionObserver adds a .v class that fades/slides elements in.
  • Scroll-progress bar: a thin gradient bar driven by scrollTop / scrollHeight.
  • Animated counters: numbers count up when they enter view.
  • Infinite marquee: duplicate the row and translate it linearly for a seamless loop (reviews, trust logos).
  • Hover lift: transform: translateY(-4px) + a larger shadow on cards.

5 · "Show, don't tell" widgets

  • Before/After slider: two stacked layers with a draggable handle clipping width.
  • Device toggle: one mockup, two CSS widths (desktop ↔ phone) that reflow via a .mobile class — no second file needed.
  • Element demo modal: each "change" card opens a realistic, animated mini-preview of that element.
  • Animated concept tiles: tiny CSS animations that visualise an abstract idea (e.g. an AI answer citing the brand).

6 · The single-file constraint

Inline all CSS and JS. Avoid <iframe src="other.html"> in anything you want to share as one file — instead, build a self-contained mockup. This came directly from a real lesson: the live-preview iframe needed a second file, so we replaced it with an inline mockup.

Hard-won lesson

If a stakeholder says "I only want to share one file," audit for external references (iframes, image src, font files). Inline or mock everything, then grep to confirm zero external paths remain.

Revenue by city, channel mix, growth trend.

The demo pattern that makes it shine

  • Seed + localStorage: a seed() function generates realistic data; load()/save() persist it in the browser so the demo feels alive and survives refreshes.
  • Reset button: one click restores the seeded demo — perfect before a live pitch.
  • Charts: Chart.js renders revenue/funnel/growth visuals that read from the same data.
  • Same design system: reuses the token + dark-mode approach for visual consistency with the website.
Why no backend (yet)

A browser-storage demo proves the workflow and wins buy-in before anyone spends on servers, auth or databases. Build the real backend only once the concept is approved (see §08 & §10).

09 · SEO & GEO Playbook

Get found on Google — and cited by AI

SEO gets you ranked. GEO (Generative Engine Optimization) gets you quoted by ChatGPT, Gemini, Perplexity and Google AI Overviews. This is the emerging edge, and most competitors aren't doing it yet.

What helps you get cited by AI

  • Clear, factual content — quotable statements, not marketing fluff.
  • Direct question→answer format — matches how people (and AI) ask.
  • Structured headings & clean HTML — easy for engines to parse.
  • Schema markup (JSON-LD) — explicit facts: business type, rating, prices, area served.
  • Authoritative expertise — expert-reviewed, original content.
  • Brand mentions & citations across trusted sites.
Practise what you preach

The plan itself ships with MedicalBusiness and FAQPage JSON-LD in its <head> — a live demonstration of exactly the technique we're selling.

The content strategy that scales

The biggest discoverability win is targeted landing pages, multiplied across three axes:

AxisExample pagesCaptures
🏙️ City"Full Body Checkup in Noida"local "near me" + city searches
🩺 Ailment"Diabetes Screening", "Thyroid Tests"symptom/condition searches
👨‍👩‍👧 Age / life-stage"Health Checkup for Women 40+"demographic searches
📰 Blog hub"Signs of Vitamin D deficiency"informational + AI-citation traffic

Combined: 60+ cities × 14+ conditions × 4+ life-stages ≈ 3,000+ targeted pages — each a doorway from search and AI into a booking.

How to scope, schedule and quote

Phase the work so the client gets value early and commits incrementally. Lead with outcomes; let budget follow trust.

Week 3

Content, SEO & GEO

Targeted pages, blog seed, schema, speed, forms, WhatsApp.

Talking budget — the humble way

  • Lead with value, not price. "Here's what this unlocks for bookings and trust" before any number.
  • Anchor to outcomes & phases. Quote per milestone so the ask feels proportionate and low-risk.
  • Ask, don't assume. "What budget range are we working within for Phase 1A, so I can shape the scope to fit?"
  • Offer a clear first step. A small, well-defined Phase 1A is an easy yes and builds the trust that funds the rest.
Note

This doc intentionally keeps specific figures out — quote based on your team's rates and the agreed scope. The structure above is what makes any number feel reasonable.

12 · Prompts & Communication

How to get this quality out of an AI partner

The output is only as good as the direction. These patterns consistently produced strong results.

Prompt patterns that worked

  • Set a persona + a bar. "Act as the best UI/UX designer; make it a banger / out of the park." Raises the ceiling on effort and polish.
  • Give constraints, not just goals. "Single HTML file," "dark mode," "works on mobile," "don't mention cost" — constraints shape better output than vague praise.
  • Name the audience. "For a non-technical CEO," "appeal to Gen-Z and older users." The tone and vocabulary follow.
  • Iterate in small, concrete asks. "Remove this line," "make the boxes smaller," "the checkmark looks odd." Specific edits converge faster than full rewrites.
  • Ask for options when unsure. e.g. "single file with a full embed, a light mockup, or two files?" — decide trade-offs explicitly.

Communicating with non-technical stakeholders

  • Translate every feature into an outcome. "Schema markup" → "so Google & AI understand and recommend you."
  • Use effort tiers, not jargon. 🟢🟡🔴 communicates scope without a spec.
  • Show a working thing. A live mockup or demo beats any description.
  • Keep it less verbose. One-line "Now vs After" pairs; subtle, aesthetic, direct.
  • End with the ask. Make the client's next step small and obvious.
13 · Replication Checklist

Do it yourself, start to finish

A peer can follow this to reproduce the same engagement on a new client.

  1. Audit the current product. List concrete problems as a user. Capture screenshots/notes.
  2. Define the design system. Pick palette + 1 display + 1 body font. Write tokens as CSS variables with a dark-mode override.
  3. Prototype the new front-end as one self-contained HTML file. Add reveal-on-scroll, counters, and conversion sections.
  4. Build a demo of any tooling (CRM/dashboard) on localStorage + Chart.js. Add a "reset demo" button.
  5. Research the production stack — front, back, DB, integrations, hosting — and write the phase plan + timeline.
  6. Write the SEO/GEO strategy — schema, Q&A content, and the city × ailment × age page matrix.
  7. Build the pitch deck as an interactive HTML file. Narrative arc, plain-English change cards tagged by goal + effort, live element demos, a roadmap, and a client ask-list.
  8. Scope the aesthetic of the deck independently from the product (own colours/fonts) so it reads as strategy.
  9. Enforce the single-file rule. Inline CSS/JS, mock anything that would need a second file, then grep for external src/iframe references.
  10. Iterate with the stakeholder in small, specific edits until it's subtle, clear and convincing.
  11. Ship a knowledge bank (this document's pattern) so the team inherits the know-how.
Quality bar to hit

Opens by double-click · works offline · looks great in light and dark · responsive on a phone · printable to PDF · zero external dependencies.
